# ランキングの設計（案）

今日のお題で「今日の上位○%」を出す。利用者と決めたい事が残っているので、まだ案。

## 方針

- 名前を出さない。自分の位置（上位○%）だけを見せる。名前の欄が無いので悪口や XSS（画面への書き込みの乗っ取り）が起きず、上位を取っても名誉が無いのでズルをする意味も薄い。
- 点数はサーバーが決める。ページは「どう引いたか」だけを送り、サーバーが同じ計算（`src/game/physics.js`）をやり直して距離を出す。狙っている間は時間が止まるので（v1.1）、1 投は置き場と引き方だけで決まる。
- ソースは公開している。隠して守る部分は作らず、ページの側に秘密を置かない。
- 無料の枠だけで動かし、超えたら止まるだけ（請求は来ない）にする。ランキングが止まっても、ゲームは今までどおり遊べる。

## 置き場所: Cloudflare（無料プラン）

| 部品 | 使い道 | 無料の枠 |
| --- | --- | --- |
| Workers | 1 投を受け取り、計算し直し、上位○%を返す | 1 日 10 万リクエスト、1 リクエストの CPU 10 ms。超えるとエラー（1027・1102）で、課金は無い |
| D1 | 記録 | 1 日に読む行 500 万・書く行 10 万、5 GB。2026-09-01 から、超えると失敗する |

- 1 投の計算は、いちばん長い場合（どこにも当たらず 30 秒飛ぶ）で 1.9 ms（平均）、最悪 3.5 ms だった（手元の Node で測った）。10 ms に収めるため、1 リクエストで計算するのは 1 投だけにする。
- AWS（Bot と同じ）も無料の枠で動くが、上限が無いので、大量に送りつけられると請求が膨らむ。だから使わない。
- Firebase の無料プランでは、サーバーで計算し直す機能（Functions）が使えない。だから使わない。

出典: [Workers の上限](https://developers.cloudflare.com/workers/platform/limits/)・[Workers の料金](https://developers.cloudflare.com/workers/platform/pricing/)・[D1 の料金](https://developers.cloudflare.com/d1/platform/pricing/)・[D1 の無料枠の強制（2026-09-01）](https://developers.cloudflare.com/changelog/post/2026-09-01-d1-free-tier-limit-enforcement/)・[Rate Limiting](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/)

## 流れ

1. ページは、今日のお題を 1 投するたびに `POST /throw` を送る。中身は次の 4 つだけ。
   - `date`: お題の日付
   - `pad`: 置き場の番号（縦長か横長かで、置く側が変わるため）
   - `pull`: 引いた量（x, y）
   - `player`: 端末のランダムな ID
2. Worker は次の手順で処理する。
   1. 形を確かめ、合わなければ捨てる。数字は有限か、`pull` の長さは 3 以下か、日付は日本時間の今日か、`pad` は今日のお題の置き場か、`player` は決まった形の文字列か、を見る。リクエストの大きさは 1 KB まで。
   2. `dailyChallenge(date)` から的と置き場を作り、`launch` と `advance` で計算する。
   3. 距離を記録し、上位○%を返す。
3. ページは、サーバーが返した距離と上位○%を結果の欄に出す。通信できないときは、今までどおり手元の計算の結果だけを出す。共有と投稿の文にも「上位○%」を足す。

## 順位の付け方

- 1 人（`player`）の今日の記録は、3 投のうちいちばん近かったもの。
- 300 km 未満（「ぴったり」）は全員を同じ順位にする。プログラムで最適な投げ方を探す人がいても、上手な人と並ぶだけになる。
- 上位○% は「自分より近かった人の割合」。0% は出さず、ぴったりは「ぴったり（上位 N%）」とする。

## 守り

| 何を | どう守るか | 残る穴 |
| --- | --- | --- |
| 嘘の距離 | 距離は送らせない。サーバーが計算する | 無し |
| ありえない投げ方 | 長さ・置き場・日付をサーバーが確かめる | 無し |
| 最適な投げ方を探すプログラム | 300 km 未満を同じ順位にし、名前も出さない | 防げない（得もしない） |
| 1 日 3 回を超える | 同じ `player` は 3 投まで数える | `player` を作り直せば、また投げられる。ログインが無いと防げない |
| 大量に送る（順位の割合を歪める・枠を使い切る） | IP ごとの回数の制限（Rate Limiting、10 秒に数回）。IP のハッシュごとに 1 日の投数の上限 | 携帯の回線では大勢が同じ IP を使うので、上限は緩めにする |
| 枠を使い切らせる | 超えても止まるだけで、請求は来ない | その日のランキングが止まる |
| ほかのサイトからの呼び出し | CORS で `https://amefuritell.github.io` だけ許す | ブラウザの外からは呼べる（上の制限で抑える） |
| SQL への入り込み | 値は必ずプレースホルダーで渡す | 無し |
| 個人の情報 | IP は持たない。日ごとに替わる秘密の値を混ぜた IP のハッシュだけを持ち、記録は 7 日で消す | 無し |
| 鍵の漏れ | ページには鍵を置かない。Cloudflare の鍵は GitHub の secret か手元だけ | 無し |

Turnstile（ボットかを見分ける仕組み。無料）は、今は使わない。外のサイトからスクリプトを読み込む必要があり、それは README の決まりに反するため。荒らされたときの次の手として残す。

## 置き場が画面で変わる

今日のお題の置き場は、画面の向きで変わる（`placePad`）。縦長なら上か下、横長なら左か右で、候補は 3 通りある。だから「誰でも同じ」は、同じ向きの画面どうしの話になる。サーバーは `pad` の番号でこの 3 通りを受け付け、順位は 3 通りをまとめて付ける。置き場によって難しさが違えば不公平になる。直すなら、置き場を画面の向きに頼らない 1 か所にそろえる（別のループで扱う）。

## 計算の食い違い

ブラウザ（iPhone の Safari など）と Worker では、`Math.sin` などの最後の桁が違うことがある。かすめる投げ方だと、7,200 刻みの間に結果が分かれうる。正式な距離はサーバーの計算とし、ページはサーバーが返した距離を出す。

## コードの置き場所

`meteor/server/` に Worker を置く。`src/game/physics.js`・`daily.js`・`targets.js` をそのまま import する（同じ計算を使うため）。配備は wrangler で行う。

## 利用者に決めてほしいこと

1. この形（名前なし・上位○%・ぴったりは同率）でよいか。
2. Cloudflare のアカウントを作る（無料）。配備を GitHub Actions で行うなら、API トークンを amayadori の secret に入れる。
3. 記録の保存期間（案: 7 日）。
